# 그늘길 코스 — 설계

> 목표: 햇볕이 강한 시간에 그늘이 많은 길로 코스를 짠다. 코스마다 "그늘 68%"처럼 얼마나 그늘인지 보여준다.
> 원칙: 운영 중 외부 API 호출과 서버 부담을 늘리지 않는다. 데이터는 PC에서 한 번 만들어 서버에 올린다.
> 작성: 2026-10-10

## 1. 그늘은 어디서 생기나

| 그늘 | 언제 | 데이터 |
|---|---|---|
| 나무 (가로수, 공원 숲, 하천변 숲) | 하루 종일, 해가 높을수록 사실상 유일한 그늘 | **ESA WorldCover 2021** 10m 토지피복도의 "나무" 칸. 전 세계 무료 (CC BY 4.0, 출처 표시). 한국 전체 약 200MB |
| 건물 | 해가 낮을 때 (아침, 늦은 오후). 정오 전후엔 짧다 | 건물 높이 자료 필요 (OSM은 높이가 드묾, 브이월드 건물통합정보는 별도 키). **2단계** |
| 다리·고가 밑 | 하루 종일, 짧은 구간 | OSM `bridge=yes` 밑 구간. 2단계 |

**1단계는 나무 그늘만** 쓴다. 한여름 오후(해 고도 50~70°)에 실제로 그늘을 만드는 건 거의 나무뿐이라, 가장 효과가 큰 부분부터.

## 2. 해 위치

- 날짜·시각·위치로 해의 고도와 방위를 계산한다 (NOAA 공식, 외부 호출 없음).
- 해 고도 35° 이상 + 5~9월 낮이면 "그늘 우선"을 기본으로 켠다. 사용자가 칩으로 끌 수 있다.
- 안내: "지금 해가 높아요 (고도 62°). 그늘이 많은 길 위주로 짰어요." 해가 진 뒤엔 그늘 표시를 숨긴다.
- 2단계(건물 그늘)에서 방위가 쓰인다: 해가 동쪽에 있는 아침엔 남북으로 난 길의 서쪽 보도가 그늘, 같은 식.

## 3. 그늘 지도 (PC에서 한 번, 서버에 저장)

1. WorldCover 타일 6장(한국 범위)을 받아 "나무" 칸만 남긴다.
2. 20m 격자 비트맵으로 줄여 저장한다 (20m 칸 안에 나무가 절반 이상이면 그늘). 0.1° 블록별로 압축해 서버 SQLite에 넣는다 (예상 20~40MB). 숲이 넓게 이어져 있어 압축이 잘 된다.
3. 서버는 경로를 10m 간격으로 짚어 그늘 칸 위에 있는 비율을 계산한다. 길 가장자리 가로수까지 잡도록 주변 1칸(20m)도 본다. 코스 하나에 수 ms, 외부 호출 없음.

## 4. 코스에 반영

| 코스 | 그늘 우선일 때 |
|---|---|
| 공원 코스 (산책로 바퀴) | 공원 목록을 그늘 비율 순으로도 정렬 (공원별 숲 비율은 미리 계산해 저장). 바퀴 후보(바깥/안쪽 고리) 중 그늘 많은 쪽 선택. TMAP 호출 0 |
| 공원 여러 곳 순환 | 공원 조합 점수에 공원별 숲 비율 가점 |
| 순환 코스 | 지금도 방향별 후보 2~3개를 만든다 → 그늘 비율로 순서를 정함 (추가 호출 없음) |
| 강변 | 왕복 방향 두 쪽 중 강변 숲이 많은 쪽으로 (경로 짜기 전에 강선 주변 그늘을 지도에서 비교) |
| AI 추천 | "그늘", "햇빛 피해서", "시원한 길" → 그늘 우선 칩 |

- 모든 코스 카드에 **그늘 %** 배지. 같은 거리면 그늘 많은 코스를 위에.
- 거리를 많이 희생하지 않는다: 목표 거리 ±15% 안의 후보끼리만 그늘로 고른다.

## 5. 정확도의 한계 (사용자에게 그대로 말하기)

- WorldCover는 위성 기준 2021년 상태. 가로수가 작거나 듬성듬성한 길은 덜 잡힌다.
- 1단계는 건물 그늘을 모른다. 빌딩 숲 사이 길은 실제보다 그늘이 적게 나온다.
- 그래서 "그늘 %"는 "나무 그늘이 덮는 비율"로 표시한다.

## 6. 단계

| 단계 | 내용 |
|---|---|
| S1 | 해 위치 계산 + 그늘 지도 만들기(PC) + 서버 그늘 비율 계산 + 카드 배지 |
| S2 | 공원/순환/강변 코스 선택에 그늘 반영, 그늘 우선 칩, AI 문장 인식 |
| S3 (선택) | 건물 그늘 (높이 자료 확보 시), 다리 밑 |
