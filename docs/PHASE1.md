# Phase 1 설계 — 기록 + 음성 코칭

> 목표: 서버 없이, 로그인 없이, **폰과 이어폰만으로 달리거나 걷고 기록이 남는 앱.**
> 작성: 2026-10-05

## 1. 화면 구성

| # | 화면 | 내용 |
|---|---|---|
| 1 | **홈** | 큰 시작 버튼 하나. 위에 목표 칩: `자유` `거리` `시간` `페이스`. 아래에 최근 기록 한 줄, 이번 주 누적 거리. 하단 탭: 홈 / 기록 / 설정 |
| 2 | **카운트다운** | 3·2·1 (음성 같이). GPS 신호 잡는 동안 "GPS 찾는 중" 표시 |
| 3 | **운동 중** | 큰 숫자: 시간, 거리, 현재 페이스. 상태 배지: `달리는 중` / `걷는 중` / `일시정지`. 목표가 있으면 진행 막대. 버튼: 일시정지 / **길게 눌러 종료** (주머니 속 오작동 방지) |
| 4 | **종료 요약** | 경로 그림, 거리·시간·평균 페이스·칼로리·오르막 합계, 1km 구간표, 달리기/걷기 비율. 버튼: 저장 / 버리기 / GPX 내보내기 / 삼성헬스에 저장 |
| 5 | **기록** | 날짜별 목록, 탭하면 4번과 같은 상세 화면 |
| 6 | **설정** | 체중(칼로리 계산용), 음성 알림 주기, 알림 항목 선택, 자동 일시정지 켜기/끄기 |

- 화면을 꺼도 기록과 음성은 계속된다. 알림창에 시간·거리와 일시정지/재개 버튼이 보인다.
- 걷기와 달리기는 **모드를 고르지 않는다.** 시작만 누르면 앱이 자동으로 판별한다.

## 2. 음성 코칭

| 시점 | 예시 |
|---|---|
| 시작 | "운동을 시작합니다. 목표 5킬로미터." |
| 1km마다 (기본값, 설정에서 0.5km / 5분 / 10분으로 변경) | "1킬로미터. 이번 구간 6분 12초. 총 시간 6분 12초." |
| 목표 절반 | "절반 왔어요. 지금 페이스면 31분에 끝나요." |
| 목표 임박 | "목표까지 500미터." |
| 페이스 목표가 있을 때 | 목표보다 15초 이상 느리면 "조금 빠르게", 빠르면 "조금 천천히" (같은 말 반복은 1분 간격 제한) |
| 자동 일시정지/재개 | "일시정지." / "다시 시작합니다." |
| 목표 달성 | "목표 달성! 5킬로미터, 31분 4초." |

- 음악을 듣고 있으면 음성이 나오는 동안 **음악 소리만 잠깐 줄인다** (끊지 않음).
- 한국어 TTS는 안드로이드 기본 음성을 쓴다. 추가 비용 없음.

## 3. 걷기/달리기 자동 판별

- **주 신호: 걸음 리듬(분당 걸음 수).** 폰의 걸음 센서로 측정. 달리기는 보통 분당 150~190보, 걷기는 90~130보.
- **보조 신호: GPS 속도.** 걸음 센서가 없는 폰이나 애매한 구간(빠른 걷기 vs 느린 조깅)에 쓴다.
- 상태가 **10초 이상 유지될 때만** 바꾼다 (신호 대기 한 번에 걷기로 바뀌지 않도록).
- 기록의 모든 지점에 `달리기/걷기/정지` 상태를 저장한다 → 요약의 비율, 칼로리 계산에 사용.

## 4. 칼로리

ACSM 대사 공식 (경사도 반영):
- 달리기: VO₂ = 0.2 × 속도(m/분) + 0.9 × 속도 × 경사 + 3.5
- 걷기: VO₂ = 0.1 × 속도 + 1.8 × 속도 × 경사 + 3.5
- kcal/분 = VO₂ × 체중(kg) / 200

구간마다 달리기/걷기를 구분해서 계산하고 합한다. 화면에는 "약 312kcal"처럼 대략치로 표시한다.
체중을 입력하지 않으면 65kg 기준으로 계산하고 설정을 안내한다.

## 5. GPS 정확도

- 1초 간격, 고정밀 모드 (Google Play 위치 서비스).
- 정확도 25m보다 나쁜 지점은 버린다.
- 사람이 낼 수 없는 속도(초속 12m 이상)로 튄 지점은 버린다.
- 자동 일시정지: 속도가 거의 0이고 걸음도 없는 상태가 5초 이상이면.

## 6. 기술 구조

```
[화면 (Compose)] ←── StateFlow ──── [WorkoutService : 포그라운드 서비스]
                                         ├─ LocationSource   (GPS)
                                         ├─ StepCadence      (걸음 센서)
                                         ├─ TrackFilter      (튀는 값 제거)
                                         ├─ ActivityClassifier (걷기/달리기)
                                         ├─ WorkoutTracker   (거리·시간·구간·칼로리)
                                         ├─ CoachEngine      (언제 무슨 말을 할지)
                                         └─ VoiceAnnouncer   (TTS + 음악 볼륨 줄이기)
                                                │
                                         [Room DB: Workout, TrackPoint]
                                                │
                                   [GPX 내보내기]  [Health Connect → 삼성헬스]
```

- 판단 로직(TrackFilter, ActivityClassifier, WorkoutTracker, CoachEngine, 칼로리)은 안드로이드에
  의존하지 않는 순수 Kotlin으로 만든다 → 단위 테스트로 검증 가능.
- 권한: 위치(정밀), 알림, 신체 활동. 앱이 화면에 떠 있을 때 서비스를 시작하므로 "백그라운드 위치"
  권한은 필요 없다 (심사가 까다로운 권한이라 피하는 게 좋다).
- 로그인 없음, 모든 기록은 폰에만 저장.

## 7. 지도

- 네이버 지도 SDK는 네이버 클라우드 가입과 키 발급이 필요하다 (**사용자가 직접 해야 함**).
- 키가 준비되기 전까지 요약 화면의 경로는 **지도 없이 선으로만** 그린다. 키가 생기면 그 선을 지도 위에 얹는다.
  다른 작업이 지도 때문에 막히지 않는다.

## 8. 구현 순서

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| M1 | 권한 + 포그라운드 서비스 + 시간·거리 기록 (화면 꺼도 유지) | 에뮬레이터에 가짜 GPS 경로 재생 |
| M2 | 운동 중 화면 + 음성 코칭 + 목표 | 에뮬레이터 + 실제 폰으로 산책 |
| M3 | 걷기/달리기 판별 + 자동 일시정지 + 칼로리 | 단위 테스트 + 실제 러닝 |
| M4 | DB 저장 + 종료 요약 + 기록 목록 | 에뮬레이터 |
| M5 | GPX 내보내기 + Health Connect(삼성헬스) | 파일을 Strava에 올려보기, 삼성헬스에서 확인 |
| M6 | 네이버 지도 연결 | 키 발급 후 |

가장 위험한 부분(화면이 꺼진 상태에서 오래 정확하게 기록하기)을 M1에서 먼저 검증한다.
